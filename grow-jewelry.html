Grow Jewelry

A full-stack product that helps jewelry stores turn a customer's vague idea into realistic concepts and a quote-ready lead while the customer is still in the store.

Visit Grow Jewelry

The business problem

I had worked in a jewelry store as a graphic designer and videographer, so I was familiar with the problem.

Customers would come in wanting a custom order—from a wedding ring to a name pendant or necklace—but usually had only a vague understanding of what they wanted. In my experience, showing customers how the piece could look could nearly double the conversion rate on the spot.

  • The issue: a traditional CAD jewelry design can take days or weeks to create.
  • Drawings do not give customers the same feeling as a realistic rendering of the finished piece.
  • If the customer leaves without a clear visual, their initial excitement can turn into “I'll think about it.”

The solution: use AI and a constrained design decision tree to generate realistic concepts on the spot, so customers can envision what they want before they leave the store.

Product boundary

Grow Jewelry is a fast visualizer and lead-to-quote workflow. It helps a customer and jeweler agree on a direction; it does not replace manufacturing-ready CAD or a jeweler's final technical review.

From an idea to a quote-ready lead

I designed the product around the conversation that already happens at a jewelry counter:

  1. A customer opens the store's design link or scans its QR code.
  2. They choose the piece, style, text, metal, stones, emblem, and other relevant details.
  3. The app turns those choices into a structured prompt and selects the matching visual references.
  4. Two image variants generate asynchronously and appear as they finish.
  5. The app saves the customer's choices, generated concepts, and contact information as a lead.
  6. The store owner chooses the exact concept, adds pricing and production details, and prepares a private quote link.

This makes the AI generation useful inside a business workflow. The output is not only an image; it is attached to the customer's selections and carried forward into a quote the owner can review and send.

Constraining the design space

This is the user decision tree for the custom jewelry designer. It keeps the model focused on combinations that are relevant to real jewelry orders instead of asking the customer to write a prompt.

  • Customers make familiar product decisions rather than prompt-engineering decisions.
  • Each style owns its allowed options, defaults, prompt template, and reference images.
  • Inputs such as text, metal color, emblem, and style are validated before generation.
  • The same selections are persisted for the owner, so the generated concept stays connected to the eventual quote.

Prompts and testing

There are pre-selected image assets for most combinations of the jewelry design. Based on what the user selects, the relevant style, typography, metal, and emblem references are attached to the request sent to the image model.

The user's choices are turned into a prompt through a structured prompt-generation pipeline. I tested and iterated on these prompts over a few months until they produced more accurate, realistic, and consistent results.

The prompt system reinforces requirements that image models often miss:

  • spell the customer's text correctly
  • keep every letter and emblem connected as one manufacturable piece
  • use gold for the structure and diamonds for the visible decorative surfaces
  • preserve the selected lettering style, metal colors, emblem, and front-facing product view

Each name-design request produces two variants. One uses Gemini 3 Pro Image and the other uses Gemini 3.1 Flash Image. This gives the customer two interpretations and lets me compare quality across a higher-detail model and a faster model instead of depending on one output.

The image-model APIs changed frequently with new releases, which could disrupt prompts that had worked before. Preview models could also be throttled, lowering the quality of generations. Because this is a commercial project for paying customers, I needed a repeatable way to catch those changes before they reached users.

I developed prompt templates and techniques designed to survive model upgrades, then built an internal Generation Lab to test a new model before upgrading:

  • run eight representative generations at once with controlled customer inputs and prompt variants
  • compare Gemini 3 Pro Image and Gemini 3.1 Flash Image outputs side by side
  • inspect the exact prompt, reference images, model, generation time, and success or failure state for every result
  • diagnose whether a bad result came from the model release, prompt template, style configuration, or attached references

The application persists the normal request and result records for each test, so the evaluation uses the same generation path as the customer product. This makes prompt iteration inspectable instead of relying on whichever image looked best most recently.

Tech stack and implementation

  • React

    I already had experience with React, and its component model worked well for a multi-step, cross-device design flow.

  • TypeScript

    Shared types keep customer selections, API payloads, generated results, and owner workflows consistent across the application.

  • Next.js

    Next.js supports dynamic store, design, quote, and owner routes while keeping the frontend and API in one deployable application.

  • Tailwind CSS

    I used Tailwind because it fit the UI system I wanted and made it practical to keep the customer and owner screens responsive.

  • Prisma

    Prisma defines the relational data model and provides a typed query layer for accounts, requests, results, leads, quotes, and generation jobs.

  • PostgreSQL

    PostgreSQL stores the transactional record of each customer request, generation attempt, selected result, and quote.

  • Supabase

    Supabase hosts PostgreSQL and provides authentication for store owners and account-scoped dashboard access.

  • Vercel

    Vercel hosts the Next.js application and keeps longer-running image generation attached to the request lifecycle while the UI polls for results.

  • Google GenAI SDK

    The GenAI SDK sends the generated prompt and selected image references to the two Gemini image models.

What I learned

The most important part of this project was not simply calling an image model. It was turning an open-ended customer request into a small set of useful decisions, preserving those decisions through generation, and giving the store owner enough context to take the next commercial step.

I also learned that visual AI needs an evaluation loop. Model names and prompt wording change, but the product requirements stay concrete: correct spelling, believable materials, connected construction, accurate customer choices, and a result a jeweler can confidently discuss. Persisting prompts and attachments made those failures easier to diagnose and improve.
